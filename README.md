1. Створіть базовий абстрактний контракт для обліку балансів та дочірнього контракту стейблкоїна. У дочірньому контрактi необхідно переписати внутрішній метод переказу так, щоб під час кожної транзакції 1% від суми автоматично відправлявся на окремий гаманець скарбниці, а 99% діставалися отримувачу. Результатом має бути успішне перерозподілення коштів між відправником, отримувачем та скарбницею при виклику переказу.

2. Необхідно створити два незалежні базові контракти, які мають функції з однаковими назвами та повертають різні текстові ролі. У дочірньому контрактi слід явно перевизначити цей метод, щоб він повертав нову роль, а також створити додатковий метод для виклику базової функції за правилами порядку успадкування. Перевірка полягає у відсутності помилок компіляції та отриманні очікуваних текстових значень при виклику обох методів.

3. Створіть два контракта, які взаємодіють через спільний інтерфейс. Перший контракт виконує роль сховища та безпосередньо приймає та зберігає криптовалюту. Другий контракт працює як брокер: він не тримає кошти на своєму балансі, а лише перенаправляє запити користувачів на поповнення чи зняття до першого контракту. Результатом є успішне поповнення та зняття коштів користувачем через брокера з відповідною зміною балансу всередині сховища.
